0. RÉSUMÉ EN 10 LIGNES
--------------------------------------------------------------------------------
- Application Wear OS 3+ (minSdk 30, targetSdk 34, compileSdk 34), package `com.example.chrono`, nom affiché
  « Super StopWatch » (fixe, toutes langues).
- Au départ : « ajouter à l'appli chrono Samsung un tour déclenché par le bouton physique bas ». L'appli Samsung
  n'est pas modifiable (code fermé) => on a reconstruit une appli complète.
- Projet 100 % généré par Claude dans une conversation, SANS environnement de compilation côté Claude :
  le code n'a JAMAIS été compilé par Claude. L'utilisateur envoie le code sur GitHub, GitHub Actions compile,
  l'utilisateur colle les logs d'erreur, Claude corrige. Toute modification doit donc être écrite avec une grande
  prudence sur les API (pas de test possible).
- Langue de travail : FRANÇAIS. L'utilisateur est sur Windows, n'utilise pas Android Studio, installe via adb.
- Livrable à chaque tour : un fichier ChronoWatch.zip (projet Gradle complet) + explications courtes.
- Interface : Compose for Wear OS (androidx.wear.compose 1.4.0) + Compose BOM 2024.06.00, Kotlin 1.9.24,
  compiler extension 1.5.14, AGP 8.5.2, Gradle 8.7 (installé par le workflow, pas de wrapper jar).
- Fonctions : chrono, tours, bouton physique, tile, complication, pastille « Ongoing Activity », historique,
  QR codes, suivi avancé (allure + exercice/repos), verrou tactile, mode éco, AOD, mode clair, 3 langues,
  10 logos, sliders à sous-menu min/max, explications par appui long, bague rotative, départ random (voix + coup de feu),
  sliders en listes rondes (échelle log), arrêt auto sur la dernière interaction, etc.
- v14 (version actuelle) : sliders de temps/distance du suivi avancé en listes rondes log ; goals = vibration seule (jamais de tour), 3 couches
  (UI / alarme / service de premier plan GoalService) ; arrêt auto = (temps - dernière interaction) > valeur ; DÉPART RANDOM (RandomStart.kt,
  SoundPlayer.kt, 23 fichiers audio). Voir 1.2, 4.5, 4.7, 4.11.
- Signature : build `release` signé avec la clé de DEBUG de la machine GitHub => clé différente à chaque build
  => il faut désinstaller avant de réinstaller (`adb uninstall com.example.chrono`).

1. HISTORIQUE DU PROJET ET MÉTHODE DE GÉNÉRATION
--------------------------------------------------------------------------------
1.1 Méthode (importante pour continuer)
  a) L'utilisateur formule des modifications (souvent une longue liste, parfois ambiguë).
  b) Claude répond d'abord par des QUESTIONS (parfois via un popup interactif à 3 questions max, parfois en texte
     numéroté OUI/NON/MODIFIER) quand il y a une ambiguïté, puis génère.
  c) Claude écrit les fichiers dans /home/claude/ChronoWatch, les zippe en /mnt/user-data/outputs/ChronoWatch.zip
     et le présente avec `present_files`.
  d) L'utilisateur glisse le dossier `app` (et les fichiers racine) dans GitHub (« Add file > Upload files »).
     Le dossier caché `.github` N'EST PAS pris par le glisser-déposer : le fichier
     `.github/workflows/build.yml` doit être créé/édité À LA MAIN dans l'interface web GitHub.
  e) GitHub Actions compile. En cas d'échec l'utilisateur colle le log ; Claude corrige (souvent une seule erreur
     visible à la fois, le compilateur Kotlin s'arrêtant à la première phase en échec).
  f) L'utilisateur télécharge l'APK (Releases ou Artifacts) et l'installe avec adb sur la montre.

1.3 Erreurs de compilation déjà rencontrées (à ne pas refaire)
  - Import du Tile : en tiles 1.4.x la classe `Tile` est `androidx.wear.tiles.TileBuilders.Tile`
    (PAS `androidx.wear.protolayout.TileBuilders`). Resources/Timeline restent dans protolayout.
  - `remember { }` interdit dans le contenu d'un `ScalingLazyColumn { }`/`LazyColumn { }` (scope non composable) :
    calculer avant la colonne.
  - Clash de signature JVM : une propriété `var x by ... private set` génère `setX(T)`. Ne JAMAIS déclarer une
    fonction `setX(valeur)` à un seul paramètre du même type (ex. `setEcoBrightness(Int)`). Les fonctions
    publiques du projet prennent (Context, valeur) ou s'appellent `updateX`.
  - ListenableFuture : on utilise `CallbackToFutureAdapter.getFuture<T> { c -> c.set(x); "tag" }`
    (androidx.concurrent:concurrent-futures), pas Guava.
  - Les résultats `ScalingLazyColumn` centrent le 1er élément et estompent les bords : source de « black box ».
    La liste des tours utilise donc `LazyColumn` (foundation) simple.
  - Wear `Text` : pour que deux composables de même nom ne se télescopent pas, `itemsIndexed` de foundation est
    importé avec alias (`as lazyItemsIndexed`) dans Screens.kt.
1.4 Choses jamais vérifiées sur une vraie montre (ne pas les affirmer)
  - Que la bague tactile Samsung envoie bien des événements rotatifs aux appli tierces (`onRotaryScrollEvent`).
  - Que « Forcer l'arrêt » Samsung est classé `REASON_USER_REQUESTED`.
  - Rendu exact du tile (ColorFilter, ressources vectorielles), complication, pastille Ongoing Activity.
  - Lisibilité réelle des QR codes selon la version, rendu du glyphe ⚠️ (emoji) et des caractères chinois.
  - Changement d'alias de lancement (icône) : délai de rafraîchissement du launcher.
  - Les logos 1 et 2 ont été dessinés « à l'aveugle » (chemins SVG) ; les logos 3 à 10 sont tracés depuis
    apercu_logos.svg (rendu contrôlé hors Android, pas sur montre).
  - v11 : le glissement vers la droite de l'historique peut être concurrencé par le geste « retour » du système
    (contournement tenté par une sémantique de défilement horizontal) ; la sentinelle d'arrêt forcé repose sur
    l'annulation des PendingIntent / alarmes par « Forcer l'arrêt » (comportement AOSP, non vérifié sur Samsung) ;
    la fermeture par les applis récentes repose sur ApplicationExitInfo (reason USER_REQUESTED ou description
    « remove task » / « stop … ») ; l'affichage permanent logiciel (FLAG_KEEP_SCREEN_ON + luminosité 0,01) ;
    la mise à zéro de l'écart chrono -> cercles mesure la ligne de base avec TextMeasurer (TextLayoutResult.lastBaseline) ;
    restauration de la position de liste via rememberScalingLazyListState(initialCenterItemIndex, initialCenterItemScrollOffset).
  - v12 : recalage des objectifs sur les tours (hypothèse : un tour par segment, repos compris) ; curseurs entiers ; précision temps ;
    luminosité du système sur l'écran des QR (BRIGHTNESS_OVERRIDE_NONE) : rien de tout cela n'a été exécuté sur une montre.
  - v14 : (a) service de premier plan GoalService (type specialUse, Android 14) : jamais lancé sur montre, comportement des « applis en veille »
    Samsung inconnu ; (b) vibrations des goals écran éteint / appli en arrière-plan : tout le chemin (alarme + service + USAGE_ALARM) est une
    hypothèse non vérifiée (déjà le point faible de la v13) ; (c) volume du flux ALARME : setStreamVolume peut être refusé ou limité
    (Ne pas déranger, restrictions Samsung), restauration non vérifiée ; (d) texte de la pastille pendant l'attente (Status.TextPart de
    wear-ongoing 1.0.0) : rendu sur le cadran non vu ; (e) MediaPlayer.create(... USAGE_ALARM) sur le haut-parleur de la montre, latence et fin
    de lecture ; (f) wake lock partiel <= 110 s et alarmes setAlarmClock écran éteint ; (g) onTaskRemoved du service : appelé ou non selon le
    fabricant ; (h) les voix et les coups de feu n'ont jamais été écoutés sur montre.
  - Syntaxe Kotlin vérifiée avec kotlinc 1.9.24 (aucune erreur d'analyse), mais PAS de compilation Android complète.

4. DÉTAILS PAR DOMAINE
--------------------------------------------------------------------------------
4.1 Chrono (Stopwatch.kt)
  - Temps = heure murale : `startedAt` (System.currentTimeMillis) + `accumulated`. elapsed() = accumulated +
    (now - startedAt) si running, plafonné à la limite d'arrêt auto. Pas de boucle de service : un process tué ne
    perd pas le temps.
  - Persistance SharedPreferences("stopwatch") : run, acc, start, nonce, lapsFile, laps, exitSeen, seen (dernier
    passage dans l'appli), sentinel (posée ?), boot (compteur de démarrages).
  - Tours (`laps`, plus récent d'abord, Lap(index, lapTime, total)). Stockage : préférences (mode normal) ou fichier
    `files/laps.log` en AJOUT SEUL (mode éco : lignes `L,idx,lap,total` et `U` pour annuler) ; `syncLapStore()`
    migre une fois quand le mode éco change (à appeler AVANT de modifier la liste).
  - reset(c, vibrate) : si !running et acc>0 -> History.add(Session). stopAndReset(c, at, silent) pour la notif et
    l'arrêt forcé. `finishReset()` annule les alarmes (auto-stop, segments), efface le fichier de tours.
  - Fermeture / arrêt forcé (checkForcedStop, appelé par load()) : deux détections indépendantes, puis
    stopAndReset(c, instant, silent) (séance enregistrée) :
      1. SENTINELLE : au Start (et à chaque load() si running) `armSentinel` pose une alarme RTC non réveillante à
         +300 jours qui retient un PendingIntent (requestCode 7, SentinelReceiver). « Forcer l'arrêt » annule alarmes
         et PendingIntent ; si `sentinel`=true et `PendingIntent.getBroadcast(FLAG_NO_CREATE)` renvoie null => arrêt
         forcé. Exception : si le compteur de démarrages (Settings.Global.BOOT_COUNT) a changé, c'est un redémarrage
         de la montre (alarmes effacées) : le chrono continue comme en v10. Désarmée à stop/reset/arrêt auto.
      2. ApplicationExitInfo : processus tué à la demande de l'utilisateur (REASON_USER_REQUESTED / USER_STOPPED, ou
         description « remove task » / « stop <paquet> ») avec timestamp > startedAt (applis récentes, arrêt forcé).
    Instant d'arrêt retenu : horodatage de sortie du système, sinon dernier passage dans l'appli (`seen`), sinon maintenant.
    Un processus tué pour manque de mémoire ne déclenche rien : le chrono continue (temps = heure murale).
    Rejeté : onDestroy/isFinishing (le geste « quitter » de Wear finit aussi l'activité), service avec onTaskRemoved
    SANS service de premier plan (arrêté ~1 min après la mise en arrière-plan), savedInstanceState (faux positifs).
    v14 : GoalService, lui, est de premier plan et a un onTaskRemoved (voir 4.7).
  - Arrêt auto (v14) : Settings.autoStopSec (SECONDES, 0 = OFF, jusqu'à 86400 ; clé sl_autoStopS). Le chrono s'arrête quand
    (temps - lastAct) > valeur ; `lastAct` = temps de chrono de la dernière interaction (Start / reprise, tour manuel, annulation de tour,
    coup de feu du départ random), persisté (clé « lastAct » de « stopwatch »), remis à 0 au reset. À l'arrêt le temps est figé EXACTEMENT à
    lastAct + valeur (elapsed() plafonné, enforceAutoStop). UNE seule vibration d'arrêt (buzzAutoStop : jamais deux à moins de 1,5 s ;
    l'état est écrit en commit() avant la vibration). Alarme (armExact, AutoStopReceiver) reposée à chaque interaction (+5 ms) ;
    vérification aussi à chaque tick / onStart / load / lap / relâchement du curseur.
  - Horloge (v13) : le temps écoulé = accumulated + runDelta(). runDelta() = SystemClock.elapsedRealtime() - startedEl (monotone,
    insensible aux recalages de l'heure) tant que la montre n'a pas redémarré (BOOT_COUNT identique à `startBoot`) ; sinon heure
    murale (now() - startedAt), ce qui garde le chrono vivant après un redémarrage. Persistés : start, startEl, startBoot.
    Start / Stop / Reset écrivent les préférences avec commit() (pas apply()) pour ne jamais perdre un changement d'état.
  - Vibrations : buzz(c, strong, alarm) (tour = 55 ms, start/stop = double 140 ms, amplitudes × Settings.vibePct) ;
    alarm = true (arrière-plan : objectifs, arrêt auto ; = !Segments.uiVisible) => AudioAttributes USAGE_ALARM : sans cela,
    VibratorManagerService ignore les vibrations d'un processus d'arrière-plan (IGNORED_BACKGROUND) ;
    en éco : une impulsion courte. Frontières d'objectif : Stopwatch.buzzLogged(c, false, alarm) = vibration d'un tour,
    uniquement si Settings.trackVibe ; jamais de tour créé (voir 4.7).
  - Formats : fmtMain (mm:ss, h:mm:ss, ou secondes seules si secMode), fmtTenth (.d), fmtFull. JAMAIS plus que les
    dixièmes à l'écran.
4.2 Interface principale
  - Colonne : [haut : temps + cercles, collés en bas de leur zone, poids = topPct] [espace gapBtnLap] [bas : liste]. La
    frontière est le curseur « Haut de l'écran ». Le bas démarre en haut de sa zone.
  - Liste des tours : LazyColumn ; contentPadding bas = hauteur de la zone (n'importe quel tour peut monter en haut) ;
    sans clés d'items : on compense nous-mêmes l'insertion en tête (voir LaunchedEffect(itemCount)) : en haut et
    autoScroll => reste en haut (nouveau tour visible) ; sinon `scrollToItem(idx + d, offset)`.
  - Colonnes : n°, total, tour (+ marqueur ▲▼), allure, écart. Largeurs mesurées avec `rememberTextMeasurer` sur les
    valeurs réelles ; `Row.requiredWidth(max(somme, availW))` + `Arrangement.SpaceBetween` ; `overflow = Visible`,
    jamais de rognage. Moyenne optionnelle en 1re ligne.
  - Bague (Ring) : snake de longueur snakePct (1..100 % de la circonférence), tête = couleur forte, queue = couleur du
    cercle (dégradé sweep). Avancement : (temps depuis le dernier tour) / (meilleur tour) ; 60 s s'il n'y a pas de tour ;
    si Segments.enabled() : avancement du segment exercice/repos courant. Pas de limite basse (>= 1 ms).
  - HoldRing : arc plein de la couleur de référence qui se remplit pendant tout appui long (Ui.hold).
  - Écart chrono -> cercles : Row des cercles avec Modifier.layout ; décalage = gap% * hauteur - (hauteur de ligne -
    ligne de base) du chiffre (mesurée une fois avec TextMeasurer) : 0 % = le bas des chiffres touche le haut des
    cercles, valeur négative (jusqu'à -10 %) = chevauchement. Taille des chiffres lue dans le bloc layout (derivedStateOf
    pour le passage à 1 h : pas de recomposition à chaque dixième).
  - Triangles ▲▼ (option Settings.showMarkers, défaut oui) : relMarker(tour, référence) ; référence = tour précédent
    (laps[i+1] dans la liste récente d'abord, rows[i-1] dans une séance) ; en suivi avancé avec objectif réglé
    (Settings.seriesLen = nbRep) = tour de même rang dans la série précédente (décalage de nbRep).
  - Cercles (v13) : chrono arrêté avec un temps (!running && accumulated > 0 = `finished`) => « Reset » est affiché « Terminer »
    (même action, séance enregistrée) et, si l'option « Bouton annuler / suppr. » est active, « Annuler » devient « Suppr. » :
    HoldButton -> Stopwatch.discard(c) = remise à zéro SANS History.add. Sans l'option, il n'y a pas de 3e cercle donc pas de suppression.
  - Icônes du haut (28 dp, centrées ensemble) : au repos réglages/historique/[aide]/[suivi] (appui simple) ; en activité
    [réglages si runIcons]/[suivi] (appui long) + cadenas (appui long déverrouille) quand verrouillé.
4.3 Verrou tactile

    par maintien du cadenas, ou après N minutes (autoUnlock). Un Box plein écran consomme tous les gestes, les icônes

4.4 holdToConfirm (Components.kt)

    (`setFromFraction`). `curve = 2` (autoUnlock, aodDelay) : échelle quadratique. `choices` : valeurs discrètes (plus utilisé pour les
    précisions depuis la v14). `stepProvider` : pas imposé (hold = 0,1 s ; nbRep = 1 ; randMin/Max/Vol = 1 ; distance = précisionDist ;
    exTime et restTime = précisionTime) ; la valeur est toujours un MULTIPLE du pas (ancré sur 0, pas sur lo).
  - v14 : LISTES RONDES LOG. `nice` : 0 = non, 1 = temps (secondes, `NiceValues.time`, 0 puis 1 s ... 24 h), 2 = distance (mètres,
    `NiceValues.dist`, 0 puis 0,1 m ... 100 km). Le 1er cran est toujours 0. Sliders concernés : precisionDist, precisionTime, distance, exTime,
    restTime, autoStop (clé « autoStopS »). nbRep reste linéaire. `niceEff()` = liste filtrée sur [lo, hi] et sur les multiples du pas
    (`NiceValues.isMultiple`, 0 toujours accepté) ; `snapNice()` recale la valeur après un changement de précision / de plage / une relecture.
    Précision 0 = aucune contrainte. Sous-menu min/max : mêmes listes (`rangeFraction`, `rangeValue`, `niceBelow`, `niceAbove`, min < max).
    Affichage : `fmtDur` (« 45 s », « 1 min 30 s », « 2 h 05 min ») et `fmtDist` (« 400 m », « 1,5 km »).
  - v14 : `noRange = true` => pas de sous-menu min/max (appui long = InfoScreen seule) : precisionDist, precisionTime, randMin, randMax, randVol.
    `hasRange` = choices == null && !noRange. `clampTo` : contrainte appliquée après chaque réglage (randMin <= randMax).
  - v12 : `isInt = true` => valeur, lo et hi du sous-menu min/max sont des ENTIERS (nbRep, qrVer, qrEc, colR/G/B, ecoBright, vibe,
    autoUnlock, autoStop, aodDelay, tailles chrono/btn/lap, exTime, restTime). Avant, les bornes du sous-menu étaient décimales
    (ex. 1,99 / 34,65 pour nbRep) et rendaient la valeur décimale. Les autres curseurs sont décimaux, arrondis aux décimales de
    leur pas (`quant`, `decsFor`) pour que la valeur réelle = la valeur affichée ; `fixRange()` arrondit les bornes du sous-menu.
  - `kind` : 0 brut, 1 durée en secondes, 2 durée en minutes ; `display()` formate avec fmtDur / fmtDist, utilisé par SliderRow et RangeScreen.
  - Appui long sur un slider (SliderRow) => RangeScreen : explication (Info.byKey[clé]) puis deux SliderBar Min/Max sur
    les bornes d'origine, écart min 1 %, bouton « plage d'origine » à maintenir. Retour : `Ui.rangeFrom`. Curseurs sans sous-menu
    (noRange : précisions, départ random) : InfoScreen seule. Interrupteurs / cases / logos : appui = action, appui long = InfoScreen
    (`Ui.openInfo(clé)`). Retour : `Ui.infoFrom`. Les listes (Réglages, Suivi) gardent leur position (Ui.savedPos),
    oubliée au retour à l'écran principal.
  - Persistance : clés `sl_<key>`, `sl_<key>_lo`, `sl_<key>_hi` (floats). Arrêt auto : clé « sl_autoStopS » (NOUVELLE en v14 ; l'ancienne « sl_autoStop », en minutes, est ignorée). ecoBright ne persiste pas sa valeur (0 % à
    chaque activation du mode éco). `persistSliders(ctx)` à chaque relâchement.
  - SliderRow(spec, accent, enabled, unit, fmt, onRelease). Aimant aux extrémités (<3 % -> 0, >97 % -> 1), aucune

4.7 Suivi avancé (TrackScreen + Segments.kt + RandomStart.kt)
  - En haut : précisionDist et précisionTime (listes rondes log, sans sous-menu). Puis distance par tour (0 = pas de colonne allure), temps
    d'exercice (0 = aucun objectif), répétitions (1 … 100, entier, linéaire), repos (0 = aucun), interrupteurs « Vibrations des objectifs »
    (trackVibe, défaut oui) et « Recalage des objectifs » (trackRecal, défaut NON). Tout en bas : DÉPART RANDOM (voir 4.11).
  - Frontières : la j-ième frontière (j >= 1) est la fin du j-ième segment du cycle (nbRep exercices, puis le repos s'il est > 0,
    `Segments.perCycle()`). Identifiée par son INDEX j (stable), pas par son instant. `boundaryTime(j)`, `crossedCount(e)`, `nextBoundary(e)`.
  - GOALS (v14) = VIBRATION SEULE, JAMAIS de tour (ni auto, ni rien dans la liste). La vibration est celle d'un tour (buzzLogged(c, false,
    alarm)). Elle a lieu à chaque frontière, repos compris, même si un tour manuel tombe 0,1 s à côté (alors les deux vibrent). Constat v13 :
    ils ne vibraient jamais. Trois couches redondantes :
      1. UI : MainActivity appelle `Segments.check(c, "ui")` à chaque tick tant que l'écran est allumé (uiVisible).
      2. ALARME : `Segments.schedule` pose `armExact` (setAlarmClock, sinon exacte, sinon inexacte) sur la prochaine frontière
         -> SegmentReceiver -> `Segments.onAlarm` (check avec tolérance 250 ms, puis replanification).
      3. SERVICE de premier plan léger `GoalService` (type specialUse), actif quand le chrono tourne ET (trackVibe OU départ random) :
         garde le processus et ses alarmes en vie écran éteint (Samsung : applis en veille). Reprend la notification d'Ongoing (même id).
         `onTaskRemoved` : appli fermée depuis les récentes => stopAndReset (séance enregistrée). `onDestroy` en pleine séquence de départ
         random => RandomStart.onServiceDestroyed (annule tout, volume restauré).
  - DÉDOUBLONNAGE : `segDone` (SharedPreferences « stopwatch ») = index de la dernière frontière traitée, écrit en commit() AVANT la vibration.
    check() ne vibre que pour j > segDone ; plusieurs frontières franchies d'un coup = une seule vibration ; une frontière franchie depuis
    plus de FRESH_MS (4 s) est marquée traitée sans vibrer (réouverture tardive). `syncSignature` (« segSig ») recale en silence si les réglages
    d'objectif changent en cours de séance. Journal « segDiag » (12 dernières lignes : alarmes posées, vibrations, chemin) = `Segments.diagText`.
    `boundaryListener` : point d'extension appelé à chaque frontière traitée (branché par RandomStart.load).
  - Recalage (v12, Segments.shift) : le tour n° k = fin du segment n° k. Décalage = total du dernier tour − fin prévue du segment k
    (`nominalEnd(k)`), DÉDUIT de la liste des tours (annuler le dernier tour l'annule aussi ; un redémarrage ne le perd pas). Ne supprime
    aucune vibration. IGNORÉ quand le départ random est actif. Ex. O = [10,10,10,20(R)] : tours à 8 / 20 / 31 s -> objectifs 18 / 30 / 51 s.
    `Settings.seriesLen` (triangles ▲▼) = `perCycle()` avec le recalage (hors départ random), sinon nbRep.
  - `randShiftMs` (clé « randShift » de « stopwatch », `addRandShift`, remis à 0 par `resetProgress`) : décalage EXPLICITE des objectifs du départ
    random quand le chrono n'est pas figé ; `totalShift() = shift() + randShiftMs`.
  - Allure : `fmtPace(lapMs, distM)` -> « 3'32/km » ; la colonne n'existe que si track && colPace && distance > 0.

4.11 Départ random (RandomStart.kt, SoundPlayer.kt) — nouveau en v14
  - Réglages (Suivi avancé, tout en bas ; sous-réglages visibles seulement si ON) : `randStart` (ON/OFF), `randMin` / `randMax` (0..60 s,
    entiers, min <= max garanti ; `randMinSec` / `randMaxSec`), `randVol` (0..100 % du max du flux ALARME), `randFreeze` (« Chrono figé pendant
    l'attente », défaut ON), choix des sons `randMarks` (1..3), `randReady` (1..3), `randShot` (1..5) : un appui sélectionne ET joue
    (RandomStart.preview, au volume du curseur ; aperçu arrêté à l'arrêt de l'activité). Utilisable si Settings.track && randStart (`enabled()`).
  - Séquence : le début de CHAQUE répétition d'exercice (la 1re incluse ; jamais le repos) se fait au coup de feu. « À vos marques » (voix)
    -> « Prêts » (voix) -> délai random -> coup de feu. Instant du tir = fin de « Prêts » + random(min, max) (hypothèse documentée).
  - Synchro son / chrono (correctif post-v14) : standard athlétisme = le chrono part au DÉBUT du signal (attaque), pas à son pic. Les pistes de
    tir sont coupées pile sur l'attaque (t = 0). Le lecteur du tir est CHARGÉ pendant l'attente (SoundPlayer.prepare, au passage en WAIT, avant le
    calcul de shotAt) ; RandomStart.fire() fait : state = GO en mémoire, SoundPlayer.startPrepared() (start() immédiat), puis
    Stopwatch.randomShot (horodatage du chrono dans ses 1res lignes) ; écriture disque / alarmes / notification viennent après. Repli : play()
    classique si le chargement échoue. La latence propre au haut-parleur (quelques dizaines de ms) n'est pas compensée (jamais mesurée sur la montre).
    Site de vérification : verif_coup_de_feu/index.html (hors projet Android).
    Compensation audio (Settings.randLat, 0..5000 ms, sous-menu min/max actif, kind = 3 -> fmtMs) : SON, VIBRATION de départ et DÉBUT DU CHRONO doivent coïncider.
    randomShot() : chrono figé -> startedEl = t0 + comp ; non figé -> tour auto à elapsed() + comp ; vibration et tour auto différés de comp (shotHandler).
  - Machine d'états (`RandomStart.state`, persistée dans les préférences « randstart » : st, frozen, first, shotAt, bT) :
    IDLE -> MARKS -> READY -> WAIT -> GO -> IDLE. `waiting` = MARKS..WAIT (le texte remplace le chrono, le bouton ANNULE, pas de tour manuel) ;
    `active` = MARKS..GO (service et wake lock gardés). Déclencheurs : 1re répétition = `Stopwatch.start` -> `RandomStart.tryStart` (séance neuve
    seulement ; une reprise démarre normalement) ; suivantes = `Segments.boundaryListener` -> `onBoundary` (frontière suivie d'une répétition non
    repos, `isExerciseStart`, détectée à moins de 5 s).
  - Freeze ON : le temps est figé exactement à la frontière (`Stopwatch.freezeAt`), l'attente est exclue des temps, tours et historique ; au tir
    `Stopwatch.randomShot` reprend, fait le tour automatique, enregistre l'interaction (lastAct) et vibre. Freeze OFF : le chrono continue
    (1re répétition : `startImmediately`), au tir tour auto + `Segments.addRandShift(t - boundT)` (retard réel). Dans les deux cas
    `Segments.resync` + `schedule` (objectifs re-synchronisés même sans recalage). Tour automatique omis pour la toute première répétition (0:00).
  - Annulation : bouton (physique ou écran) pendant l'attente => `RandomStart.cancel(c, true)` : sons stoppés, volume restauré, chrono arrêté ou
    resté arrêté (`Stopwatch.haltForCancel`), pas de tir. Reset / suppression / arrêt auto annulent aussi (cancel(c, false)).
  - Écran éteint : wake lock partiel <= 110 s (se libère seul), GoalService pendant toute la séquence, minuteur en processus (Handler) +
    alarme de secours `RandomStartReceiver` (requestCode 8, `onAlarm` ; `fire` idempotent). Processus tué pendant l'attente : détecté par
    `RandomStart.load` : séquence annulée, chrono arrêté (sauf état GO), volume restauré (`AlarmVolume.restorePending`).
  - Pastille : pendant une attente FIGÉE, `Ongoing` affiche `RandomStart.ongoingText()` (Status.TextPart « Départ random… ») au lieu du chrono.
  - SoundPlayer.kt : `Sounds.res(kind, n)` (0 marques, 1 prêts, 2 tir ; langue FR/EN/ZH de l'appli ; références directes R.raw.* pour que le shrink
    ne supprime rien) ; `AlarmVolume` : règle le flux ALARME à randVol % du max, mémorise le volume d'origine au 1er détenteur, le restaure au dernier
    (ignoré si l'utilisateur l'a modifié entre-temps ; persisté dans « sound » : saved / applied ; rétabli par restorePending) ; `SoundPlayer` :
    MediaPlayer.create avec AudioAttributes USAGE_ALARM + CONTENT_TYPE_SONIFICATION, un son à la fois, filet de sécurité (durée + 2,5 s),

  - Clés SharedPreferences NOUVELLES en v14 : « settings » : randStart, randFreeze, randMarks, randReady, randShot ; sliders sl_randMin / sl_randMax /
    sl_randVol (+ _lo / _hi) et sl_autoStopS ; « stopwatch » : lastAct, segDone, segSig, segDiag, randShift ; « randstart » : st, frozen, first,
    shotAt, bT ; « sound » : saved, applied.
  - Fichiers audio de res/raw (23) :

6. CONVENTIONS DE CODE À RESPECTER
--------------------------------------------------------------------------------
- Toute chaîne visible passe par `S.XXX.t()` (3 langues). Ajouter une entrée dans `enum S` pour chaque nouveau texte.
- Tout nouveau réglage (interrupteur, case, curseur) a son explication dans `Infos.kt` (Info avec la même clé que le
  SliderState, ou le nom passé à ToggleRow/HalfToggle) ; une nouvelle rubrique d'aide = une paire dans HELP_SECTIONS.
- Toute nouvelle valeur numérique réglable = un `SliderState` dans `Settings` ajouté à `sliders` (sinon pas
  persisté ni accessible au sous-menu), affiché avec `SliderRow`.
- Tout nouveau booléen = `var x by mutableStateOf(..) private set` + `setX(c: Context, v: Boolean)` + clé dans load().
  Attention au clash JVM (voir 1.3).
- Aucune couleur grise en dur dans l'UI : utiliser Fg/Bg/Dim/Soft/SurfaceBtn/RowBg/OffTrack (mode clair).
  Couleurs « de couleur » : via `Palette` (accent, mid, inverse, inverseDark) ; en éco : gris.
- Toute action destructive : `Modifier.holdToConfirm { ... }` (ne pas coder sa propre vibration).
- Les espacements d'interface se règlent en % de `LocalConfiguration.screenHeightDp`.
- Le texte numérique utilise `tight(sizeSp)` (interligne 0,8 em, marges supprimées) pour que 0 % = contact.
- Les points d'entrée (Receiver, Tile, Complication) appellent `Stopwatch.load(ctx)` d'abord.
- Les lectures d'état dans une `draw lambda` ne déclenchent que le dessin (utilisé par la bague pour la performance) ;
  `TimeText` est une feuille qui lit seule `now` pour ne recomposer que le texte du temps.
- Batterie : pas de boucle quand l'écran n'est pas visible (`withFrameMillis`), mise à jour alignée sur le chiffre,
  alarmes seulement aux frontières, pas de récepteur de diffusion permanent.
- API incertaines : privilégier celles déjà utilisées dans le projet et déjà compilées ; signaler dans la réponse
  tout ce qui n'a pas pu être vérifié.

8. GLOSSAIRE
--------------------------------------------------------------------------------
- « Snake » : arc blanc/dégradé qui tourne autour de l'écran (bague) ; aussi l'arc plein de progression d'un appui long.
- « Bague » : le cercle extérieur dessiné ; « bague rotative/tactile » : l'entrée rotative du système (molette ou bezel tactile).
- « tempsDeMaintien » : durée d'un appui long (Settings.hold, 0,1–10 s, 2 s par défaut).
- « Haut » / « bas » : zone temps+cercles / zone des tours.
- « Essentiels » : réglages affichés même sans Personnalisation.
- « Suivi avancé » : menu distance/allure + exercice/repos.
- « Alias » : `activity-alias` du manifeste, utilisé pour changer l'icône de l'appli.

10. AUDIT v13 (sécurité, robustesse, batterie) — à relire avant toute modification
--------------------------------------------------------------------------------
Corrigé en v13 :
  - Vibrations d'objectifs absentes (écran éteint / appli en arrière-plan) : usage ALARME (voir 4.1).
  - Horloge : le chrono utilisait l'heure murale (System.currentTimeMillis) : un recalage de l'heure (synchro téléphone / réseau)
    faussait le temps. Maintenant horloge monotone + repli sur l'heure murale après redémarrage.
  - Persistance : Start / Stop / Reset en commit() (avant : apply(), perte possible si le processus est tué juste après).
  - Permission WAKE_LOCK déclarée mais jamais utilisée : retirée (moindre privilège). NB v14 : réajoutée (usage réel : départ random).
  - Historique : une boucle à 60 Hz par carte tournait en permanence (swipeOrHold) : elle ne tourne plus que pendant un appui
    (Channel.CONFLATED comme signal de réveil).
  - Statistiques de séance : division par zéro possible (tous les tours à 0 ms) : gardée.
  - Formats de nombres (« %02d ») : Locale.ROOT, pour ne pas dépendre de la langue du système.
  - Tableau de capacités QR (versions 5..25, L/M/Q/H) : 84 valeurs vérifiées avec une bibliothèque indépendante (python qrcode) : exact.
Vérifié, sans changement (v14 : 5 récepteurs + GoalService, tous exported=false ; permissions en plus : WAKE_LOCK, FOREGROUND_SERVICE*) :
  - Composants : 4 récepteurs `exported=false` ; tile / complication protégés par BIND_TILE_PROVIDER / BIND_COMPLICATION_PROVIDER ;
    tous les PendingIntent en FLAG_IMMUTABLE ; aucun Intent implicite ; MainActivity `exported=true` (sans filtre, ne traite aucun
    extra) : laissé tel quel car la changer sans test pourrait empêcher le lancement par les alias.
  - Aucune permission réseau, aucun log, allowBackup=false, stockage privé (SharedPreferences + files/laps.log).
  - Analyse des fichiers lus au chargement : try / catch partout (History, tours) ; plafonds (50 séances).
Limites résiduelles (connues) :
  - APK signé avec la clé de debug (usage perso) ; actions GitHub non épinglées par empreinte.
  - setAlarmClock s'affiche comme « prochaine alarme » du système sur certaines montres.
  - Rien de ceci n'a été exécuté sur une montre (aucun environnement Android côté IA). Compilation : GitHub Actions uniquement.
  - Fermeture depuis les applis récentes = stop + reset au prochain lancement (voulu) ; un « sommeil » imposé par le fabricant
    (Samsung : applis en veille profonde) peut aussi déclencher cette détection.
